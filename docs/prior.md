# 기존 프로젝트에서 확인한 제출 근거

2026-11-26에 공개 저장소 6개의 기본 브랜치를 내려받고 아래 커밋의 소스·시험 코드·결과 파일을 열어 확인했다. 아래 수치는 각 저장소에 보존된 이전 실행의 기록이다. 이 조사에서 이전 벤치마크나 테스트를 재실행하지 않았다. 웹 데모 네 곳은 HTTP GET 200 및 HTML 본문 수신까지 확인했다.

| 저장소 | 구현과 평가 근거 | 테스트와 데모 | 새 과제와 연결되는 방법 및 한계 |
|---|---|---|---|
| npuloop | E13에서 INT8 TFLite 생성 후 Arm Vela 5.2.0을 실행한다. conv-stack은 Vela의 47,832 추정 사이클, CPU op 0%, NPU 7 passes로 기록됐다. [테스트](https://github.com/sokldjs554/npuloop/blob/dd13cb558e49ef3a8ee87d54ab094df6aae06597/tests/test_intengine.py) · [데모](https://sokldjs554.github.io/npuloop/) | 장비 시간과 컴파일 추정 시간을 별도 필드로 저장하는 방법을 참고한다. 기존 cycle 수치는 당시 Ethos-U55 설정에만 해당한다. |
| npu-region-repair | Vela 변환 FlatBuffer에서 ethos-u custom op를 NPU partition으로 읽고 host 연산과 경계 텐서를 집계한다. CIFAR-10 test 10,000장, 학습 seed 3개, 33개 모델에서 원형의 host 6개·partition 7개·경계 12개가 두 구간 대체 시 0·1·0이 됐다. [판독 코드](https://github.com/sokldjs554/npu-region-repair/blob/0179f1ca4639bd505062ce4bffb9d04ba25a860c/src/nrr/compiler.py) · [모델별 CSV](https://github.com/sokldjs554/npu-region-repair/blob/0179f1ca4639bd505062ce4bffb9d04ba25a860c/docs/results/records.csv) | 순환 그래프 거부와 partition/원본 연산 수 구별을 시험한다. 데모에서 seed와 예산을 선택한다. [테스트](https://github.com/sokldjs554/npu-region-repair/blob/0179f1ca4639bd505062ce4bffb9d04ba25a860c/tests/test_compiler_guards.py) · [데모](https://sokldjs554.github.io/npu-region-repair/) | 지원 여부에 실제 변환 산출물과 대상 칩 이름을 붙이는 설계 참고. CPU 정확도와 컴파일 결과만 측정했다. |
| edgesight-soc | 2층 CNN의 INT8 weight, INT32 누산, 시프트, 포화, 동점 규칙을 RTL과 공유한다. 숫자 분류 test에서 FP 90.3517%, INT8 90.3066%. [양자화 코드](https://github.com/sokldjs554/edgesight-soc/blob/73ce8bb38c4594b16df470bf1711a210680ea7ba/sw/train2/quantize2.py) · [실험 JSON](https://github.com/sokldjs554/edgesight-soc/blob/73ce8bb38c4594b16df470bf1711a210680ea7ba/data/gen2/quant_report.json) | TinyNPU RTL 테스트벤치와 Verilator 이미지 주입 데모가 있다. [테스트벤치](https://github.com/sokldjs554/edgesight-soc/blob/73ce8bb38c4594b16df470bf1711a210680ea7ba/tb/tb_tinynpu2.v) · [데모 화면·명령](https://github.com/sokldjs554/edgesight-soc/blob/73ce8bb38c4594b16df470bf1711a210680ea7ba/docs/demo.md) | 변환 전후에 동일 입력과 참조 출력을 고정하는 방법을 참고한다. 이 수치는 숫자 분류에서 얻었고 데모는 RTL 시뮬레이션이다. |
| inference-rail | ResilientBackend가 주 backend의 timeout과 대체 실행을 기록한다. 이전 CI는 실제 Triton 2.73.0 Python CPU backend에서 게이트웨이 요청 8건을 batch 8로 처리했다. [코드](https://github.com/sokldjs554/inference-rail/blob/8a2c9a4400af176362b1ded0808bbc984c617112/app/backends/resilient.py) · [실행 JSON](https://github.com/sokldjs554/inference-rail/blob/8a2c9a4400af176362b1ded0808bbc984c617112/docs/evidence/triton-runtime-summary.json) | 느린 mock의 시간 초과 후 fallback 사용과 회로 상태를 검증한다. 공개 UI에서는 mock 시나리오를 재생한다. [테스트](https://github.com/sokldjs554/inference-rail/blob/8a2c9a4400af176362b1ded0808bbc984c617112/tests/test_resilient_backend.py) · [데모](https://inference-rail-demo-ui.onrender.com) | 런타임 오류와 사용 backend를 숨기지 않는 패턴 참고. 서비스 수준 fallback과 모델 그래프의 CPU 배치는 의미가 다르다. |
| SceneProof | YOLOX 전후처리를 공유하며 TensorRT FP32·FP16을 비교했다. T4, 배치 1, 300프레임, 3회 실험에서 추론 p50은 약 3.5·2.7ms. [검출기](https://github.com/sokldjs554/sceneproof/blob/44d9113f0a942e5fa2f4294e0821be7637b469b9/src/sceneproof/edge/detector.py) · [측정 조건과 결과](https://github.com/sokldjs554/sceneproof/blob/44d9113f0a942e5fa2f4294e0821be7637b469b9/docs/eval/gpu.md) | backend가 없을 때 사유를 기록하는 테스트와 사건 15건·기존 VLM 설명의 재생 데모가 있다. [테스트](https://github.com/sokldjs554/sceneproof/blob/44d9113f0a942e5fa2f4294e0821be7637b469b9/tests/test_gpu_bench.py) · [데모](https://sokldjs554.github.io/sceneproof/) | 같은 전처리·후처리, 순수 추론 시간과 전체 프레임 시간 분리, 저장 결과 표기를 참고한다. 실내 사건 검출 결과와 T4 측정값은 별개 과제다. |
| DriveSplat | KITTI 도로 영상에서 단안 depth의 유효 정답 픽셀 마스크와 AbsRel·RMSE 등을 계산한다. affine 정렬 결과로 AbsRel 0.3306을 보고했다. [결과 이미지](https://github.com/sokldjs554/DriveSplat/blob/ac2b6cb228ed81eaf7482f2bba49ef5d37f7b0bc/assets/results/kitti_depth_eval_metric.png) | 실제 도로 데이터에서 과제에 맞는 정답과 평가 단위를 정하는 사례다. 정렬 전후 결과는 모델 양자화 지표로 사용하기 어렵다. |

## 기여 출처

이 조사의 커밋 고정, 소스·데모 검사, 비교표 작성은 Codex가 수행했다. 기존 저장소 소유권으로 개인별 코드 작성 범위를 추정하지 않았다. SceneProof에는 소유자가 직접 작성·실행했다고 밝힌 항목, 도구가 준비한 항목 및 PR 링크가 구분되어 있다. 해당 프로젝트에서 지원자의 기존 기여를 인용할 때는 이 기록과 PR 단위로 확인할 수 있다.
